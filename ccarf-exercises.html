CCAR-F Claude Certified Architect — Foundations
CCAR-F Exercises · 28 graded drills

Twenty-eight exercises, weighted to the blueprint

Written against the thirty task statements in the official exam guide and distributed by the published domain weights, so the eight exercises on agentic architecture and orchestration match the fact that it is 27% of the exam — more than a quarter of everything you will be asked. Fifteen are graded in your browser as you type, seven are rapid classification drills, four are prose-option decision sets, two are labs you run yourself. Each checklist names the exact property the corresponding task statement is written around, so a partial score tells you which property you missed rather than just that you scored badly.

Where the exercises sit against the blueprint D1 Agentic architecture & orchestration 1–8 · 27% · D2 Tool design & MCP 9–13 · 18% · D3 Claude Code configuration 14–19 · 20% · D4 Prompt engineering & structured output 20–24 · 20% · D5 Context management & reliability 25–28 · 15%
If you only have ninety minutes: do 1, 3, 9, 15, 20 and 27. Those six cover the decisions the exam returns to most — which architecture the requirement actually wants, where a guarantee has to live, why an agent picks the wrong tool, what to do with a bloated CLAUDE.md, how vague instructions become criteria, and how to tell an attention problem from a capacity one.
Two habits these drills are built to install Almost every wrong answer on this exam is one of two moves. Proposing guidance where a guarantee is required — strengthening a prompt against a failure rate that has to be zero. And fixing a downstream component for an upstream fault — improving the synthesis agent when the coordinator assigned three synonymous subtasks. Exercises 3, 6, 17 and 22 drill the first; exercises 4, 24 and 26 drill the second. If you internalise nothing else from this page, internalise those two.
Work them without the reference solution open Every exercise reveals a full worked answer, but the checklist is the teaching device: each check is a property the exam grades on, phrased so a failure tells you what to change. Get to a partial score first, read which checks failed, fix them, and re-check — that loop is what transfers to exam day. The browser-graded editors save your text locally, so a half-finished answer is still there tomorrow.
The checks reward substance, not vocabulary They accept the several ways a competent answer phrases a thing and are strict about whether the property is present at all. A check for a scope boundary passes on “do not cover cost”, “another subagent owns that” or “out of scope for you” — and fails on “stay focused”, because that is not a thing a subagent can act on. All 180 checks on this page score full marks against their own reference answers, so if a check will not pass for you, the property really is missing.

Browser-graded writing

Write a subagent brief, a coordinator decomposition instruction, an escalation handoff payload, two disambiguated tool descriptions, a CLAUDE.md split, a Skill that actually fires, a CI review prompt, a triage rewrite, a multi-pass review architecture, a partial-failure contract and a human review layer. Hit Check and each requirement passes or fails by name.

JSON you actually write

Four exercises where your JSON is parsed and inspected: a subagent roster whose tool arrays are the enforcement surface, a structured error contract, an .mcp.json with no secrets in it, and an extraction schema that can express absence and admit what it could not read.

Classification and decision sets

Fast recall for the judgements the exam repeats: workflow or agent, which enforcement surface, which hook event, retry or stop, which config surface, which built-in tool, would a prompt even fix this, and is this a real escalation trigger.
