What this exam is actually about It is not an SDK trivia quiz, and it is not the Developer exam with different wording. Almost every item is the same question in a different costume: the system is already built, something measurable is wrong with it in production, and you must name the smallest change that fixes the actual root cause. The stem always plants the evidence — a log line, a percentage, a decomposition the coordinator logged, a count of tools, a latency figure. Find the sentence that names the observed behaviour, and the option that addresses that behaviour rather than a neighbouring one is nearly always credited.
The three shapes almost every distractor takes It advises where it should enforce — a system-prompt sentence standing in for a programmatic prerequisite, a hook, a schema constraint or a tool that was never granted. It blames a downstream component that is working correctly — the synthesis agent, the search agent, the review model — when the stem's own evidence points upstream. Or it is over-engineered relative to the ask — a routing classifier, a fine-tuned model, an ML pipeline, a consensus vote across three runs — when the stem says “most effective first step” and the cheap high-leverage fix has not been tried yet.

The six scenarios — and why they matter more here

This is the structural difference between CCAR-F and the other Foundations papers. The exam does not present sixty independent questions: it presents four scenarios drawn at random from a bank of six, and the items hang off them. A scenario establishes a system, a stack and a measured problem, and then several items ask you to reason inside it. That has two consequences worth planning around:

  • You will not see all six. Two of them will not appear at all, and you have no way to know which. So there is no scenario you can safely skip — but equally, a scenario you find hard may simply not be drawn.
  • Reading time is front-loaded. Four scenario texts read carefully once are cheaper than sixty stems read cold. Read the scenario properly the first time it appears, note its stack and its stated target metric, and skim it thereafter.

The scenario is a constraint, not decoration Every scenario names a stack and a target. Scenario 1 says MCP tools and 80% first-contact resolution, so an answer that lowers resolution to be safe is wrong even when it is good engineering. Scenario 5 says minimise false positives, so an option that would raise recall at the cost of precision is wrong there and right elsewhere. When two options both look defensible, the scenario's stated goal is the tie-breaker.

The fourteen distractor patterns

Nearly every wrong answer on this exam is one of these dressed in professional language. Learn them as a checklist and you can usually eliminate two options before you finish reading the stem. The full set, with the credited answer for each, is in the documentation's anti-pattern table.

PatternThe tempting wrong answerWhat the exam wants
Prompt as guarantee“State in the system prompt that verification is mandatory before any refund”A programmatic prerequisite that blocks the dependent tool until the prerequisite tool returned. Prompts have a non-zero failure rate; money does not tolerate one
Blame the downstream agent“The synthesis agent needs instructions to spot coverage gaps” when the coordinator's own log shows a narrow decompositionFix the component the evidence indicts. Subagents executing their assignment correctly are not the fault when the assignment was wrong
Over-engineering the first step“Deploy a routing classifier / train a model on historical tickets”The cheap high-leverage fix that has not been tried: better tool descriptions, explicit criteria, a few-shot set. “First step” in a stem is a scope instruction
Self-reported confidence“Have the agent rate its confidence 1–10 and escalate below a threshold”Explicit categorical criteria. A model already wrong on hard cases is confidently wrong on them; calibration needs labelled data, not introspection
Sentiment as complexity“Escalate when negative sentiment crosses a threshold”Escalate on the three real triggers: the customer asked for a human, policy is silent or needs an exception, or the agent cannot make progress
Bigger window, bigger model“Move to a larger context window so all 14 files fit in one review pass”Split the pass. Attention dilution is not a capacity problem, and a bigger window fills up too
Suppress the error“Catch the subagent timeout and return an empty result marked successful”Structured error context: failure type, attempted query, partial results, alternatives — so the coordinator can decide
Kill the whole run“Propagate the exception to a top-level handler that terminates the workflow”Local recovery first, then partial results plus a coverage annotation. One failed source is not a failed report
Everything required“Mark all schema fields required so no record is incomplete”Nullable/optional fields and an unclear enum member. A required field the document does not contain is an instruction to fabricate
Retry the unretryable“Retry the extraction with a stronger instruction” when the value is in a document you did not supplyRecognise the class: retry fixes format and structure errors, never absence. Route to human review or fetch the missing source
Batch the blocking“Move the pre-merge check to the Batches API for the 50% saving”Batch only what nobody waits for. No latency SLA and up to 24 hours makes it wrong for anything blocking a developer
Consolidate to disambiguate“Merge the two confusable tools into one lookup_entity that figures it out internally”Usually: differentiate the descriptions. Consolidation is a real option but it is a redesign, not a first step, and it hides the routing decision from the model
More tools, more capable“Give the synthesis agent the full web toolset so it never has to round-trip”Scoped access: one narrow cross-role tool for the common case, coordinator routing for the rest. Selection reliability falls as the tool count rises
Self-review as the check“Instruct the same session to critically review the code it just generated”An independent instance without the generator's reasoning context. A model that just argued itself into a design does not reopen the argument
Three tie-breakers for the last two options First, the structural answer beats the prose answer whenever the stem describes a guarantee. Second, the answer that addresses the evidence the stem planted beats the one that is better engineering in the abstract — a coordinator log showing three visual-arts subtasks is an indictment of the coordinator, whatever else is wrong. Third, match the scope word: “first step”/“most effective” wants the cheapest change with the largest effect, while “design”/“architecture” permits a rebuild.

Two scoring details that change how you pace Your pass/fail is decided by the total scaled score only — the per-domain percentages on your report are diagnostic, and there is no per-domain minimum to clear. So never over-invest in a domain you find hard at the cost of losing easy marks elsewhere. And there is no partial credit on multiple-response items: two right and one wrong scores the same as three wrong, so on a select-two item be as sure of your second choice as your first.

What is explicitly out of scope

The guide publishes an out-of-scope list, and it is unusually useful: several of these are things a working architect thinks about daily, so their absence changes what you should revise. None of the following is examined.

Not on this exam

  • Fine-tuning or training custom models
  • API authentication, billing or account management
  • Language- or framework-specific implementation beyond what tool and schema configuration needs
  • Deploying or hosting MCP servers — infrastructure, networking, containers
  • Claude's internal architecture, training process or weights
  • Constitutional AI, RLHF, safety training methodology
  • Embedding models and vector database internals

Also not on this exam

  • Computer use — browser and desktop automation
  • Vision and image analysis
  • Streaming APIs and server-sent events
  • Rate limiting, quotas, price calculation
  • OAuth, key rotation, authentication protocol detail
  • Cloud-provider specifics — AWS, GCP, Azure
  • Benchmarking and model comparison metrics
  • Prompt caching implementation detail (beyond knowing it exists)
  • Token counting and tokenisation specifics
Read the out-of-scope list as a distractor generator Several of these appear as wrong answers precisely because they are out of scope: an option proposing a fine-tuned classifier, a vector-store redesign, a streaming change or a cloud-specific deployment is almost always the distractor. If an option requires machinery the exam has declared out of scope, that is a strong elimination signal in itself.
