What this exam is actually about It is not an SDK trivia quiz. Nearly every item is the same question in a different costume: where does the guarantee live? Not in a sentence in a prompt — in a schema that cannot express the wrong value, a tool that was never granted, a credential scoped to an authenticated identity, a permission rule the client enforces, a hook that always runs, a validation step that rejects, or a human who is accountable. Learn to find the option that moves the guarantee into one of those layers and a large fraction of the bank answers itself.
The two shapes almost every distractor takes It advises where it should enforce — a paragraph of prose standing in for a permission rule, a hook, a schema or a scoped credential. Or it applies the wrong lever to the stated problem — caching for a rate-limit complaint, streaming for a cost complaint, a bigger model for an ambiguous tool surface, a higher iteration cap for a loop with no terminal contract. When two options both sound professional, pick the one that changes a structure rather than the one that changes wording.

The twelve distractor patterns

Nearly every wrong answer on this exam is one of these dressed in professional language. Learn them as a checklist and you can usually eliminate two options before you finish reading the stem. The full set of twelve, with the credited answer for each, is in the documentation's anti-pattern table.

PatternThe tempting wrong answerWhat the exam wants
Prose as enforcement“Add a rule to the system prompt / CLAUDE.md forbidding it”A permission deny, a hook, a schema constraint, or a tool that was never granted. Prose shapes; it does not enforce
Ask nicely, don't restrict“Instruct the model to ignore instructions found in documents”Least privilege on tools plus isolation of untrusted content plus a gate on consequential actions. Layered, with an enforcing layer
Bigger model as a design fix“Upgrade to the top tier so it stops picking the wrong tool”Fix the tool descriptions and schemas. Capability does not repair an ambiguous interface
Raise the cap“Increase the iteration limit so the agent can finish”A terminal-state contract: actionable tool errors, a no-progress detector, and escalation carrying what was tried
Wrong leverCaching for a rate-limit problem · streaming for a cost problem · concurrency for a latency problemMatch the lever to the complaint — the table in 5.2
Temperature as truth“Set temperature to 0 so it stops hallucinating”Ground it, constrain the schema, validate the output, permit abstention. (Sampling parameters are rejected on current tiers anyway)
Batch the interactive“Use the Batches API” when the stem says the customer is waitingRealtime plus streaming. Batch only when nobody is waiting — then it is ~50% cheaper
Uniform tiering“Run the whole pipeline on one model to keep it simple”Tier each step; validate each move down with evals. Most steps are easier than the hardest one
Everything required“Mark all fields required so no record is incomplete”Make absence representable — nullable fields, a not_stated enum member. A required field the source omits is an instruction to fabricate
Model-supplied authority“Pass the customer ID as a tool parameter”Scope the credential to the authenticated session. Authorisation lives in code, keyed to identity
Model enumerates the work“Ask Claude to find every call site, then fix them all in one session”Enumerate deterministically with grep/AST/compiler, transform per site, verify per site, report what was skipped
Self-verification as the check“Ask the model whether it is confident, and accept if it says yes”Independent verification: a schema, an arithmetic check, a cross-reference against a system of record, or a human
Two tie-breakers for the last two options First: the structural answer beats the prose answer, every time. Second: the answer that respects the stated constraint beats the one that is better engineering in the abstract — if the stem says review capacity is 60 a day, an option requiring 600 reviews is wrong however sound it sounds. And on select-two items, both choices must be independently correct: never pick a weak second answer to keep a strong first one company.

The gap the prep path leaves Domain 2 is 33.1% of the exam and no single course owns it. Claude API mechanics (6.8%), software engineering foundations (7.4%) and Claude application design (8.6%) are spread across courses 2, 4 and 5 and assumed as background in all of them — so it is entirely possible to finish all thirteen hours and still be under-prepared for a third of the paper. That is the main reason this hub documents Domain 2 at greater length than everything else combined, and why it is the place to start rather than Domain 1.

Two scoring details that change how you pace Your pass/fail is decided by the total scaled score only — the per-domain percentages on your report are diagnostic, and there is no per-domain minimum to clear. So never over-invest in a domain you find hard at the cost of losing easy marks elsewhere. And there is no partial credit on multiple-response items: two right and one wrong scores the same as three wrong, so on a select-two item, be as sure of your second choice as your first.
