CCAR-P Exercises · 30 graded drills

Thirty exercises, weighted to the blueprint

Written against the thirty-eight objectives in the official exam guide and distributed by the published domain weights, so the six exercises on integration match the fact that it is 19% of the paper — the largest single domain. Thirteen are graded in your browser as you type, six are rapid classification drills, seven are prose-option decision sets, four are labs you run yourself. Each checklist names the exact property the corresponding objective is written around, so a partial score tells you which property you missed rather than just that you scored badly.

Where the exercises sit against the blueprint D1 Solution design & architecture 1–5 · 17% · D2 Models, prompting & context 6–9 · 13% · D3 Integration 10–15 · 19% · D4 Evaluation & optimisation 16–20 · 16% · D5 Governance, safety & risk 21–24 · 14% · D6 Stakeholders & lifecycle 25–28 · 14% · D7 Developer enablement 29–30 · 7%
If you only have two hours: do 1, 3, 10, 13, 18, 21 and 25. Those seven cover the judgements the paper returns to most — where a workload sits on the pattern ladder, which option survives the arithmetic in the stem, what least privilege actually looks like in a tool registry, which layer owns a control, how to read a measurement before optimising, prevent versus detect, and answering the question a stakeholder actually asked.
Three habits these drills are built to install Almost every wrong answer on this paper is one of three moves. Offering a detective control where a preventive one was available — logging a violation that a boundary could have made impossible. Ignoring a number in the stem — recommending a full-catalogue rollout that costs twenty-nine times the stated budget. And optimising before diagnosing — buying a bigger model for a prompt-conflict problem. Exercises 13, 21 and 23 drill the first; 3, 11 and 26 drill the second; 6, 9, 18 and 29 drill the third. If you internalise nothing else from this page, internalise those three.
Work them without the reference solution open Every exercise reveals a full worked answer, but the checklist is the teaching device: each check is a property the exam grades on, phrased so a failure tells you what to change. Get to a partial score first, read which checks failed, fix them, and re-check — that loop is what transfers to exam day. The browser-graded editors save your text locally, so a half-finished answer is still there tomorrow.
The checks reward substance, not vocabulary They accept the several ways a competent answer phrases a thing and are strict about whether the property is present at all. A check for a stop condition passes on “we stop if the lift is under 2%”, “no-go at day 90 without a confidence interval excluding zero” or “halt and do not spend the remainder” — and fails on “we will review progress regularly”, because that is not a condition anyone can act on. All 163 checks on this page score full marks against their own reference answers, so if a check will not pass for you, the property really is missing.
The same six systems throughout Thornbury Health (HIPAA clinical documentation, clinician sign-off), Calderon Financial (regulated adviser assist, no personalised advice, 3 s p95), Merrowfield Retail (40M SKUs, fixed pilot budget, 90-day payback), Aldergate Agency (accreditation boundary and a fixed date), Vantis Software (Claude Code across 120 engineers, MCP registry), Northlake Logistics (multi-agent copilot, 40k sessions/day). They carry the same constraints on the Docs page and in the mock exam, so a fact you learn here is a fact you can use there.

Browser-graded writing

Write a solution brief a review board would approve, a prompt-restructuring plan, an identity and authorisation design for an agent acting on a clinician’s behalf, a grading rubric two people could apply identically, a model-change runbook, and the one-page recommendation an executive can act on. Hit Check and each requirement passes or fails by name.

JSON you actually write

Seven exercises where your JSON is parsed and inspected: a non-functional envelope whose budgets have to compose, a context budget whose claimants have to fit the window, a least-privilege tool registry, a retrieval pipeline that cannot go stale, an evaluation harness with real gates, a risk register an auditor would accept, and a pilot-to-production plan whose gates can block.

Decision sets and labs

Seven prose-option sets on the judgements the paper repeats — build/buy, model routing, integration surface, diagnosis, governance under constraint, stakeholder communication, enablement — plus four labs you run yourself, each built so that a plausible answer visibly fails in front of you.

Done with the drills?
Sit the timed mock. It is deliberately harder than the real exam — 70 items in 120 minutes against the live 63, so the clock is tighter too, and every item is built on the same six recurring systems. 720 to pass.
